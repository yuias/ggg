# Internationalization (i18n)

ggg's interface is translated with [Fluent](https://projectfluent.org/). English (`en-US`) and Japanese (`ja-JP`) translation files are in the `locales/` directory of the repository and of the release archive.

## Choosing a language

Set `language` under `[general]` in `settings.toml`, or change it on the Settings screen:

```toml
[general]
language = "ja"   # "en" or "ja"
```

The Settings screen accepts only `en` and `ja`. The change takes effect after a restart.

Only English is built into the binary. Japanese needs the translation files from the next section.

## Overriding translations

Translations are loaded per locale, in this order:

1. The override directory `<data_dir>/ggg/locales/<locale>/`.
2. The files built into the binary (English only).

This directory is also how you enable Japanese, or replace the built-in English text. ggg does not read `locales/` from the folder it runs in.

| Platform | Override directory                                                      |
|----------|-------------------------------------------------------------------------|
| Linux    | `$XDG_DATA_HOME/ggg/locales/` (default: `~/.local/share/ggg/locales/`)  |
| macOS    | `~/Library/Application Support/ggg/locales/`                            |
| Windows  | `%APPDATA%\ggg\locales\`                                                |

To enable Japanese from the release archive:

1. Extract the archive. It contains a `locales/` folder with `en-US/` and `ja-JP/`. If you build from source, use `locales/` in the repository instead.
2. Copy the `ja-JP` folder into the override directory, so the `.ftl` files end up directly in `<override directory>/ja-JP/`.
   - Windows (PowerShell), from the extracted folder:
     ```powershell
     New-Item -ItemType Directory -Force "$env:APPDATA\ggg\locales" | Out-Null
     Copy-Item -Recurse locales\ja-JP "$env:APPDATA\ggg\locales\"
     ```
   - Linux, from the extracted folder:
     ```sh
     mkdir -p ~/.local/share/ggg/locales
     cp -r locales/ja-JP ~/.local/share/ggg/locales/
     ```
3. Set `language = "ja"` and restart ggg.

To change wording, edit the copied `.ftl` files and restart.

Rules for override folders:

- A locale folder with at least one `.ftl` file replaces the built-in files for that locale completely. The two are not merged.
- Only `.ftl` files directly inside the locale folder are read; subfolders are ignored.
- For a locale other than `en-US`, a key missing from your files falls back to the English text.
- For `en-US`, a missing key is shown as `[missing: <key>]`, so copy all English files before editing them.
- If the language cannot be loaded at all, ggg starts in English.

## For developers

### File structure

```
locales/
├── en-US/
│   ├── main.ftl       # App title, pane labels, status bar
│   ├── help.ftl       # Help screen
│   ├── settings.ftl   # Settings labels and descriptions
│   ├── dialogs.ftl    # Dialog titles and prompts
│   ├── status.ftl     # Status messages and labels
│   └── commands.ftl   # Command response messages
└── ja-JP/
    └── (same files)
```

Key prefixes:

- `pane-*`: pane titles (folders, downloads, history, details)
- `tree-*`: folder tree labels
- `status-*`: download status labels (pending, downloading, deleted, ...) and status bar text
- `cmd-*`: command response messages (errors, success)

### Adding translation strings

1. Add the key to the matching `.ftl` file in both `locales/en-US/` and `locales/ja-JP/`.
2. Name keys `{section}-{context}-{element}`, for example `help-section-main`, `settings-app-max-concurrent`, `dialog-add-download`.
3. Simple strings: `app.state.t("key")`
   ```rust
   let title = app.state.t("dialog-help");
   ```
4. Strings with variables: `app.state.t_with_args("key", Some(&args))`
   ```rust
   use fluent::fluent_args;
   let args = fluent_args! {
       "label" => field.label(),
   };
   let title = app.state.t_with_args("dialog-edit-label", Some(&args));
   ```

### Adding a language

1. Create `locales/{locale}/` (for example `locales/zh-CN/`).
2. Copy all `.ftl` files from `en-US` as a template.
3. Translate the strings.
4. Optional: add a short code for the language to the `match` in `LocalizationManager::new` (`src/util/i18n.rs`), which maps `en` to `en-US` and `ja` to `ja-JP`. Any other `language` value is lowercased and used as the locale folder name.
5. Allow the new code in the language check of the Settings screen (`src/tui/app.rs`, search for `Invalid language`).
6. Update `README.md` and `examples/settings.toml.example`.

### Embedding a locale in the binary

To make a locale work without external files, add it to `EmbeddedLocales` in `src/util/i18n.rs` and rebuild. For example, to embed `zh-CN` as well:

```rust
#[derive(RustEmbed)]
#[folder = "locales/"]
#[include = "en-US/*"]
#[include = "zh-CN/*"]
struct EmbeddedLocales;
```

Update the doc comment above the struct and the "Choosing a language" and "Overriding translations" sections of this file to match.

### Best practices

- Keep keys descriptive: `status-downloading`, not `st-dl`.
- Group related keys under one prefix (all help keys start with `help-`).
- Include context: `dialog-add-download`, not a generic `add-download`.
- Keep the formatting: emojis and special characters are part of the design.
- Check both languages in the TUI.
- Keep code and code comments in English.
